berth. the VRAM leasing service for every GPU you run

Engines ask the berthd node for a lease on a card. The node queues the request, asks the current holder to drain, waits until the driver shows the memory free, and only then grants the berth. Nothing is granted on a process exit alone, and nothing is called reserved unless the driver measured it. Every number on this page comes from the node: the driver, the host and the engines' own endpoints.

SEVERAL CARDS

One berthd governs every card in the machine. Each card it schedules has its own berth panel with only that card's leases and stowaways, and a card it only reads is marked INVENTORY ONLY. A board row, a stowaway and a lease line name their card (gpu1), and a lease on several cards lists them. The tide draws the memory of all scheduled cards together. A card passed to a VM is marked on its own panel, and the others keep serving.

BASIC AND ADVANCED

BASIC
the counters, the request KPIs, the tide, the departures board and the berths. The page opens here.
ADVANCED
adds full GPU telemetry (clocks, fan, PCIe), host CPU and memory trends, prefill and reingest KPIs, the token ledger, the leaderboard and the full request table. The header switch sets it, and the page remembers it.

GETTING AROUND

The rail under the header jumps to any section of the tab and marks the one in view. A section link opens the right tab when you share or reload it. Every panel folds from the chevron in its head and stays folded between visits. The tab counts say how many voyages and engines each tab holds.

On a phone the tabs sit along the bottom edge, and the menu button opens the node's versions, the last successful read, the detail level and the retry. Times read relative, with the exact clock in the title. When a read goes stale, a retry on the connection pill reads the node at once.

The log's filter matches the kind, the engine and the detail, and the chips carry live counts. LATEST jumps back to the newest row. The board sorts by vessel, hold, status and age. An alert card stays dismissed until it clears or changes level. A ticket copies its JSON or a link to that voyage.

THE STATUS WORDS

BOARDING
waiting in the queue for a free berth
DOCKED
the lease is active and the engine runs from its HOT weights in VRAM
CASTING OFF
the holder was asked to drain and is finishing
PARKING
a draining engine is moving its weights to RAM instead of dropping them, until the driver shows the residual gone
WARM
parked: the weights are in RAM, a small residual stays on the card, and a resume brings it back at its own priority with no reload
ADRIFT
the lease is released and the memory is on its way out
AGROUND
the release stalled, and the memory is not coming back on its own

Each state shows as a shape and its word together on every panel. A dot is working, a ring is waiting, a half-filled circle is in transition, a triangle needs attention, and a square is stopped. A magenta CONTESTED flag on a docked row means the driver saw other VRAM holders at grant time. A green WARM flag marks a parked engine, and its title gives the RAM it holds and how long it has been parked. A boarding row carries a Q flag with its place in the queue and the node's estimate when it sent one. A ticket names the tier the weights live in, HOT or WARM, and gives the exact terminal command as a copy button. CARD RANKING on the engines tab shows how the node orders two engines at one priority inside the juggle window: the config order, or card hours over seven days.

THE COUNTERS

COLLISIONS AVOIDED
grants that waited for a held card instead of loading on top of the holder
VRAM HANDED OFF
peak measured bytes of every lease whose memory the card then showed freed
DRAINS
holders asked to give the berth back
AGROUND CAUGHT
stuck releases caught before the card stayed dirty
STOWAWAYS CAUGHT
VRAM holders found on a card with no lease
CONTESTED
grants made while another holder shared the card
REFUSED
requests turned away when their wait ran out
JUGGLES STOPPED
handoffs between two engines at one priority that the ranking settled instead of flipping the card back and forth

Every count is an event the node saw. Berth never estimates what might have happened.

CONTEXT AND KV

Context residency draws each request's cached, fresh and generated tokens against the model's context window, so a request that would not fit is plain to see. The KV pool shows each engine's live slots (the llama.cpp family's /slots) against their windows, with marks at 75% and 90%. Longer ranges show the per-minute peak fill; the live slots stay live. An engine without these endpoints reports no window and no slots, and the panels say so.

GPU AND MACHINE

Each card reports power against its limit, temperature and utilisation, and in advanced mode its SM and memory clocks, fan and PCIe link. n/a means the driver did not report a value; it never means zero. The machine panel is the host: CPU, cores, memory, swap and load. Its socket line counts event-stream write timeouts and dropped slow readers, so a stalled log starts there.

THE LIBRARY

The library lists the model files on this machine, the same rows berth models prints: shelf, quant, size, and the CACHED share in the kernel page cache. COOL means half the file or more is cached, COLD less. The kernel takes those pages back when it needs the RAM, so CACHED predicts a faster reload and says nothing about RAM held. SERVED BY names the engine that has the model loaded, and EST VRAM is that engine's learned footprint, an estimate and never a reservation. The copy buttons give berth prefetch NAME and berth models show NAME.

GAMES, STOWAWAYS AND NO TICKET

A game that a hold claim matches holds the card under a claim:NAME lease, so engines drain and wait until it exits. berth hold does the same by hand. A stowaway is any process holding VRAM without a lease: Berth reports it and never stops it. A NO TICKET run is an engine started while the node was down, so it holds the card outside any lease.

FROM THE TERMINAL

The harbor reads the node and changes nothing. Switching and stopping engines from here will need a paired device (berth pair), and that is not built yet. The gateway has its own page at /gui/ on the gateway's port, where an engine with a start command can be launched. Everything this page shows is also on the terminal:

berth status
berth events -f
berth claims
berth hold --reason game
berth config check
